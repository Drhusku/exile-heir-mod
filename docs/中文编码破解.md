# EU4 汉化 mod 的中文编码规则（已破译并验证）

本文记录 **Europa Universalis IV 1.37.5** + 中文汉化 mod 环境下，
自定义文本如何写成游戏能正确渲染的中文。**问题已解决**，以下规则可直接复用。

---

## 一、结论速查

| 项目 | 要求 |
|---|---|
| 文件编码 | **UTF-8 with BOM**（无 BOM 游戏不加载该文件） |
| 文本格式 | 每个非 ASCII 字符 → **3 个字符** `[marker][b1][b2]` |
| `b1` / `b2` | 该字符 **UTF-16LE** 码位的低字节 / 高字节 |
| `marker` | `0x10` 原样 / `0x11` 低字节已 +14 / `0x12` 高字节已 −9 / `0x13` 两者 |
| 字节 `0x80-0x9F` | 以 **cp1252 对应的 Unicode 码位**存盘（如 `0x85` → `U+2026`） |
| ASCII 字符 | 原样书写，不转义 |

**低字节禁用集**（命中则 +14 并置 marker 位）：
```
00 0A 0D 20 22 23 24 2F 3A 3B 3D 40 5B 5C 5D 5F 7B 7D 7E 80 A3 A4 A7 BD
```

**高字节禁用集**（命中则 −9 并置 marker 位）：
```
20 22 5B 5C 5D 5F 7B 7D 7E 80
```

---

## 二、为什么普通 UTF-8 中文不行

实测对照（同一份内容）：

| 文件写法 | 游戏内结果 |
|---|---|
| UTF-8 **with BOM** + 普通中文 | 文件被加载，但中文全部渲染成 `????????` |
| UTF-8 **无 BOM** | **文件完全不被加载** → 界面显示 key 原名 |
| GBK 无 BOM | **文件不被加载** → 同上 |

汉化 mod 的字体（`gfx/fonts/zh-hans-{12,14,16,18,24,map}.fnt|.dds`，BMFont 位图，
face 名 `方正屏显雅宋_GBK`）其 `char id` **就是标准 Unicode 码位**：

```
char id=22825 x=391 y=513 width=16 height=18    ← 22825 = 0x5929 = U+5929「天」
char id=25252 x=850 y=893 width=16 height=18    ← 25252 = 0x62A4 = U+62A4「护」
```

字形共 21563 个，覆盖完整 Unicode 基本区。**引擎会先把文本按上述规则反转义成码位，再按码位查字形**——
所以字体侧没问题，问题在于文本必须写成转义形式。

## 三、规则是怎么破译的（可复现）

关键素材：**「简易中华都护府」mod（创意工坊 3577645463）把同一批 key 存了两份**：

- `CnPro_*_l_chinese.yml` —— 明文中文（参照物）
- `CnPro_*_l_english.yml` —— 转义编码（待解）

逐 key 对齐后即可建立"汉字 → 字节序列"映射。验证结果：

```
解码后与明文版完全一致: 54 条
不一致                : 0 条
```

样例：

| key | 原始码位序列 | 解码结果 |
|---|---|---|
| `CnPro_set_duhufu_title` | `10 29 59 10 1D 67 10 FD 90 11 B2 62 10 36 52 10 A6 5E` | **天朝都护制度** |
| `cnpro_started.1.a` | — | **奉天承运，皇帝诏曰！** |

> **踩坑记录**：最初按原字节直接解读时，「护」会解成「抲」（U+62A4 → U+62B2）、
> 「皇」解成「瘡」、「《」解成「〘」，一度误判为"作者码表有未知变换、无法复现"。
> 真实原因是漏了 **cp1252 逆映射**——文件里 `0x80-0x9F` 这段字节是以 cp1252 对应码位存盘的。

## 四、编码 / 解码参考实现（Python）

```python
CP1252_REV = {0x20AC:0x80,0x201A:0x82,0x0192:0x83,0x201E:0x84,0x2026:0x85,
              0x2020:0x86,0x2021:0x87,0x02C6:0x88,0x2030:0x89,0x0160:0x8A,
              0x2039:0x8B,0x0152:0x8C,0x017D:0x8E,0x2018:0x91,0x2019:0x92,
              0x201C:0x93,0x201D:0x94,0x2022:0x95,0x2013:0x96,0x2014:0x97,
              0x02DC:0x98,0x2122:0x99,0x0161:0x9A,0x203A:0x9B,0x0153:0x9C,
              0x017E:0x9E,0x0178:0x9F}
BYTE2CP = {b: cp for cp, b in CP1252_REV.items()}

LOW_BAD  = {0x00,0x0A,0x0D,0x20,0x22,0x23,0x24,0x2F,0x3A,0x3B,0x3D,0x40,
            0x5B,0x5C,0x5D,0x5F,0x7B,0x7D,0x7E,0x80,0xA3,0xA4,0xA7,0xBD}
HIGH_BAD = {0x20,0x22,0x5B,0x5C,0x5D,0x5F,0x7B,0x7D,0x7E,0x80}

def encode_char(ch):
    cp = ord(ch)
    if cp < 0x80:
        return [cp]                       # ASCII 原样
    b1, b2 = cp & 0xFF, cp >> 8
    f1, f2 = b1 in LOW_BAD, b2 in HIGH_BAD
    if f1: b1 = (b1 + 14) & 0xFF
    if f2: b2 -= 9
    mk = 0x10 | (1 if f1 else 0) | (2 if f2 else 0)
    return [mk, BYTE2CP.get(b1, b1), BYTE2CP.get(b2, b2)]

def encode(s):
    out = []
    for ch in s:
        out.extend(encode_char(ch))
    return ''.join(chr(c) for c in out)

def decode(s):
    cps = [ord(c) for c in s]; out = []; i = 0
    while i < len(cps):
        cp = cps[i]
        if 0x10 <= cp <= 0x13 and i + 2 < len(cps):
            b1 = CP1252_REV.get(cps[i+1], cps[i+1])
            b2 = CP1252_REV.get(cps[i+2], cps[i+2])
            if cp in (0x11, 0x13): b1 = (b1 - 14) & 0xFF
            if cp in (0x12, 0x13): b2 = (b2 + 9) & 0xFF
            out.append(chr(b1 | (b2 << 8))); i += 3
        else:
            out.append(chr(cp)); i += 1
    return ''.join(out)
```

**写盘**：`b'\xef\xbb\xbf' + content.encode('utf-8')`（BOM 必须）

## 五、质量校验建议

1. **往返自检**：`decode(encode(text)) == text`
2. **与语料交叉核对**：把编码结果与汉化 mod 现有文本逐字比对，确认无偏差
3. **字体字形覆盖**：解析 `.fnt` 的 `char id`，确认用到的每个汉字都有字形
4. **游戏内验证**：控制台 `reloadloc` 可热重载本地化文本，无需重启

本 mod 的 `exile_heir_l_english.yml` 即按此规则生成，实测通过：
103 个汉字全部在语料验证范围内，6 个字号字体字形缺失数为 0。
